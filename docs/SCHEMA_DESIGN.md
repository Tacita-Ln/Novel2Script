# 剧本 YAML Schema 设计文档

## 1. Schema 定义（通用剧本格式）

```yaml
# 必填字段
title: string               # 剧本标题
author: string              # 原作者（或改编者）
logline: string             # 一句话故事梗概

# 角色列表
characters:
  - name: string            # 角色名
    age: int                # 年龄（可选）
    personality: string     # 性格描述
    role_type: string       # 角色类型：主角 / 配角 / 反派

# 场景列表（按顺序）
scenes:
  - scene_id: int           # 场景序号（从1开始）
    location: string        # 地点
    time: string            # 时间：日 / 夜 / 晨 / 暮 / 室内 / 室外（可自由描述）
    action: string          # 动作描述或舞台指示（可选）
    dialogues:              # 对话列表
      - character: string   # 说话角色名（需在 characters 中存在）
        line: string        # 台词内容
```

> 注：以上字段全部为转换时可能输出的内容。`action` 为非必填，由模型根据小说内容自动判断是否生成。

## 2. 设计原因

### 2.1 结构化程度适中
YAML 格式天然支持层次化数据，便于程序解析、校验和二次编辑。相比于纯文本或 JSON，YAML 对作者更友好，可直接手工修改。

### 2.2 保留剧本核心要素
- **角色独立列表**：避免在每个场景中重复描述角色，减少冗余，也便于后期统计台词量、出场次数。
- **场景顺序**：按 `scene_id` 递增，符合线性叙事习惯；若小说存在倒叙/插叙，模型会按阅读顺序排列，作者可后续调序。
- **对话与动作分离**：`dialogues` 专门承载台词，`action` 描述动作/环境，符合标准剧本格式。

### 2.3 面向小说改编的实用性
- **可量化**：可轻松统计角色台词数量、场景数量、平均台词长度，为作者提供修改依据。
- **可追问**：用户可基于输出 YAML 向 AI 提问，实现交互式打磨。
- **容错性**：允许 `action` 缺失，降低模型输出错误概率，保证至少产出可用的对话线。

### 2.4 避免过度复杂化
不区分电影、电视剧、话剧等子类型，原因：
- 小说改编的初始目标通常是“获得可阅读的剧本雏形”，而非直接投拍。
- 不同类型剧本的核心差异（如分集、分幕、音效标记）可通过后期人工或二次转换完成。
- 保持 Schema 简单，可降低模型幻觉率，提高开发稳定性。

## 3. 完整示例

假设输入小说片段（节选自《三体》开篇）：

> 汪淼站在北京近郊的田野上，抬头望向星空。三颗太阳在天空中不规则地闪烁。他喃喃自语：“这三颗太阳，真的无法预测吗？”身旁的史强点燃一根烟，说：“科学家都算不出来，你操什么心。”

转换后的 YAML 输出：

```yaml
title: 三体
author: 刘慈欣
logline: 地球文明与三体文明的交锋
characters:
  - name: 汪淼
    age: 45
    personality: 理性、执着
    role_type: 主角
  - name: 史强
    age: 40
    personality: 粗犷、务实
    role_type: 配角
scenes:
  - scene_id: 1
    location: 北京近郊田野
    time: 夜
    action: 汪淼抬头望向星空，三颗太阳不规则地闪烁。
    dialogues:
      - character: 汪淼
        line: 这三颗太阳，真的无法预测吗？
      - character: 史强
        line: 科学家都算不出来，你操什么心。
```

## 4. 使用说明

- **输入限制**：建议至少提供3个章节的小说文本（本工具可处理任意章节数，但为满足比赛核心要求，推荐使用3章以上。若不足3章，会给出提示但仍可正常转换）。
- **输出格式**：严格遵循上述 Schema 的 YAML 文本，用户可一键复制或下载为 `.yaml` 文件
- **打磨建议**：作者可手动修改 YAML 文件，例如拆分场景、增加动作细节、调整角色关系，然后重新导入工具进行后续分析

## 5. 后续扩展方向

- 支持批量处理长篇小说的多章转换
- 增加剧本质量评分（如对话密度、角色出场平衡度）
- 可选输出 Fountain 或 PDF 格式剧本
- 增加剧本类型自动识别（电影、电视剧、话剧等），并适配不同的结构要求。
